---
name: Release summary secret contract
description: Why release IDs and smoke-account values stay out of GitHub step summaries by construction, and how the contract test enforces it across every summary writer.
---

Rule: anything written to `GITHUB_STEP_SUMMARY` or a readiness diagnostic must be fixed text or a sanitized prerequisite name. Candidate build/app IDs may be recorded only in uploaded evidence files under the results directory; smoke-account credentials may only be exported by name to the native tooling, never value-expanded.

**Why:** GitHub's secret masking covers only the exact value registered in the same job. An ID that reaches a summary through a downloaded evidence artifact, a different job, or any transformation renders in clear text, and the release summary is visible to everyone who can see the pull request. Release IDs and smoke-account values are deliberately private, so privacy cannot depend on masking.

**How to apply:** the contract test in `scripts/tests` discovers every script the release workflow invokes (including through `pnpm --filter` package scripts) that writes the summary and requires each to be in its explicit inventory; a new summary-writing script fails the test until it gets static rules plus a sentinel run. Keep summary steps' `env` on the allowlist (step outcomes, needs results, non-secret env, github/runner/inputs context) and never `cat` an evidence file (branding report, Info.plist JSON, metadata) into the summary — link or name it instead. A file whose purpose is to be copied into the summary (a pre-rendered Markdown fragment) is a summary, not evidence: its producer must omit candidate IDs, and the behavioral run generates it with the real producer under sentinel IDs so a regression in the producer fails the workflow test. Diagnostics may interpolate only allowlisted runtime values; a new one must be added to the script's allowlist after confirming it cannot carry a private value (literal, assigned-once script constants are recognized automatically; copying an env value into a local variable does not launder it). Prefer denylist-style assertions over snapshots there because several tasks extend the same summary step concurrently.
